# v0.4.0-alpha.17 - A turn finishes without rereading the session

**Date:** 2026-11-13

## Highlights

- **Finishing a turn is faster on a large Journey.** The step that checks a turn's text against the
  Pi session ran about seven times per settlement, each time reading and parsing the whole file. It
  now runs once, and the later steps reuse its answer while the file is unchanged (CR157).
- **Other Journeys wait less.** Those reads held the app's one command lock, so every other
  Journey's data commands queued behind a large settlement. Shorter reads shorten that wait (CR157).
- **No change in what is checked.** A session that changed, even by a second, is checked in full
  again, and only a passing check is ever remembered (CR157).
- **Still Intel-only and unsigned on macOS;** the Windows bundle is unsigned.

## Where We Started

On the Journey with the longest history, finishing a turn took about nine seconds at the median, up
from about three before 8 November. Most of it was not the stored conversation, as first suspected, but
a safety check: each outbox and journal step re-derived the turn from the whole Pi session, a file
of over 200 MB there, to confirm the text about to be saved is the text Pi wrote.

## What Changed

- **One check, remembered.** A passing check is kept for the session's path, size and modification
  time, together with the exact turn it covered. A later step asking the same question about the
  same unchanged file answers from memory; anything else reads the file again.
- **The read that builds the item counts.** When a turn is queued for saving, the read that built
  the item is also its check, so a settlement reads the session once instead of about seven times.
- **Bounded and honest.** At most sixteen answers are kept, a read during which the file changed is
  never kept, and a refused item is never kept.

## What Does Not Change

The same Pi and the same `mirror-mind@0.44.0` core as alpha.16. The comparison itself is the
one CR126 introduced, unchanged. No file format or table changes, and nothing is stored: the memory
lives only while the app runs.

## Conscious Exclusions

- **The stored conversation is still read and rewritten at each settlement.** On a large Journey
  that is about three seconds and grows slowly; it is recaptured only if the timings after this
  release still call for it.
- **No new timing is promised.** The gain is estimated from per-phase measurements, and the
  Navigator validated the change in dev; the settlement timings of the installed app are the proof.
- **No signing or notarization,** on macOS or Windows, and **no Apple Silicon build.**

## What We Learned

The cost was not where the first guess put it. Measuring each phase, then timing the candidate
operations on a copy of the real file, moved the fix from the large, visible file to the repeated,
invisible check. A check that is repeated for safety needs to be asked once and remembered, not
asked every time.

## Next Horizon

Reading the settlement timings after this release, queuing behind a running turn, storing the intent
in a conversation, installing the Windows app from the published artifacts, and signing and
notarization.
