# v0.4.0-alpha.16 - Messages that wait for a compaction

**Date:** 2026-11-13

## Highlights

- **A message waits instead of being refused.** While a manual compaction runs, Enter and Send
  ("Send when the compaction ends") move the draft into a list above the Composer and clear the
  field for the next one. Each waiting message can be removed (CR259).
- **The queue leaves as one turn.** Messages written with no answer in between are one intention,
  so they go joined by a blank line when the conversation can send again, with any files pending in
  the Composer (CR259).
- **A failed compaction asks.** A compaction that fails may leave the context full, so the queue is
  held with the reason and two ways out, "Send now" and "Back to the composer". A refusal because
  there was nothing new to compact leaves the context as it was, and the queue goes (CR259).
- **Another Journey keeps its queue.** A queue left in a Journey that is not on screen waits there;
  the sidebar counts it beside the Journey's name, and it goes when the Journey is opened (CR259).
- **It survives closing the app, held.** After a restart the queue is back with a note, and leaves
  only on "Send now", because no compaction is running to end (CR259).
- **Still Intel-only and unsigned on macOS;** the Windows bundle is unsigned.

## Where We Started

A manual compaction rewrites the session, so the conversation cannot send until it settles. The
Composer let you type but Enter did nothing, so the next instruction had to be kept in mind, or left
in the field, for minutes and sent by hand afterwards.

## What Changed

- **The queue.** One per conversation, at most 20 messages, none blank, together no longer than one
  message. The rules are a pure module; the view is a small component above the Composer.
- **A send that fails returns to the queue.** The queue leaves the store only when the agent has the
  turn. A rollback, a cancel before any answer, or a turn that ends first holds it again with the
  reason, and nothing is written over what is being typed in the Composer.
- **The draft file.** The queue rides in the Composer draft file, which says schema 1.1.0 only while
  a message waits and stays 1.0.0 otherwise. The native validator checks the same bounds.

## What Does Not Change

The same Pi and the same `mirror-mind@0.44.0` core as alpha.15. No table in a home's database
changes. While a turn runs the Composer still steers as before, and a draft file with no queue is
unchanged.

## Conscious Exclusions

- **Not while a turn runs.** Queuing behind a live turn is a different path and is left for later.
- **Not released into a Journey that is not on screen,** because starting a turn needs the
  conversation's authority, which only the selected one has loaded.
- **Files are not queued,** only words; files pending when the queue leaves go with it, and are not
  kept across a restart, as before.
- **An older app cannot read a 1.1.0 draft file.** Send or clear the queue before going back a version.
- **No signing or notarization,** on macOS or Windows, and **no Apple Silicon build.**

## What We Learned

Waiting is a kind of sending: the person has said what they want, and the app's job is to keep it
safe until the moment it can act. Holding the words visibly, with a way back, matters more than
sending fast.

## Next Horizon

Queuing behind a running turn, storing the intent in a conversation and resolving it per turn,
installing the Windows app from the published artifacts, and signing and notarization.
