# v0.4.0-alpha.23 - The Compact layout stays inside the window

**Date:** 2026-11-23

## Highlights

- **The Compact layout no longer slides the window sideways.** In alpha.22, choosing Compact and then
  sending a message that streamed an answer moved the whole app to the left: the sidebar lost its first
  letters and views, and the portrait in the header was cut. The conversation column is now as wide as
  the window leaves it, the Journey's folder path ends in an ellipsis when it does not fit, and the
  window cannot be scrolled by following the conversation (CR277).
- **Still Intel-only and unsigned on macOS;** the Windows bundle is unsigned.

## Where We Started

The day alpha.22 was published, the Navigator updated, chose the Compact layout and sent a message.
The sidebar broke as the answer began to render. Changing the view or the size of the window did not
repair it; switching to Classic did.

## What Changed

- **Conversation column (CR277).** In the Compact layout the header lays its parts on one line. The
  column had no declared width, so that line's natural width, with a long folder path, became its floor
  and the column grew past the window: 131 px in the reproduction. It is now `minmax(0, 1fr)`.
- **Window scroll (CR277).** Following an answer calls `scrollIntoView`, which also scrolls the app
  shell, and `overflow: hidden` hides that scroll without preventing it. The shell now adds
  `overflow: clip`, which cannot be scrolled. WebKit before 16 keeps `hidden` and relies on the column
  rule alone.

## What Does Not Change

The same Pi, the same Node, the same Core (`mirror-mind@0.44.2`) and the same Conversations as
alpha.22. No schema change and no migration: the home stays at `018_drop_hook_injected`. No Rust
change, and the provider install of alpha.22 is current, so nothing is downloaded again.

## Conscious Exclusions

- **Classic and the Activity view are untouched.** Only the column width and the shell's scroll changed.
- **WebKit was not exercised.** The reproduction and the check ran in a browser engine; the Navigator
  validated the fix on macOS.
- **OpenAI sign-in** can still fail with `invalid_grant` after the page, also in Pi alone; it is not a
  Nautilus defect.
- **No signing or notarization,** on macOS or Windows, and **no Apple Silicon build.**

## What We Learned

An optional layout was validated on a Journey with a short path and an answer that did not stream, and
broke in the first real use. The gates measured what the layout looked like, not what it did to the
window when the conversation moved. The cause was two quiet defaults: a grid column that sizes itself
by its content, and a box that hides a scroll instead of forbidding it.

## Next Horizon

Nothing is waiting on this release. Refusing executable files on both routes of the external file
open, and the OpenAI sign-in, remain with the Navigator.
