# v0.4.0-alpha.22 - Claude's cache, a sidebar that says who needs you, and a contributor's round

**Date:** 2026-11-23

## Highlights

- **Claude keeps its prompt cache between turns.** With Claude through Claude Code, each message made
  Claude write the whole conversation to its cache again: on a production home, 67 of 69 turns after
  a finished answer rewrote everything, 431k tokens a turn on average. Nautilus ends Pi's process with
  every turn, and the memory of which Claude Code session to reuse went with it. The settled session
  now crosses the process boundary, and is adopted only when upstream's own reuse rule would accept it
  (CR274, PR #22 by Rodrigo).
- **An update that changes the provider does not disconnect Claude.** That change alters the installed
  Claude provider, so a connected person would have found `Unknown provider "claude-bridge"` after
  updating. The app now brings the provider up to date by itself, with no click, showing "Connected,
  updating for this version of Nautilus" in Settings; a Claude turn sent meanwhile waits for it, with a
  note, and the person's own `pi-claude-bridge` never answers in its place (CR275).
- **The sidebar can show who needs you.** A fourth view beside Recent, Pinned and Tree, Activity, groups
  every Journey as Need you (a failed or interrupted turn, an answer not yet opened, a held message),
  Working (the operation running now, with a clock) and Idle (CR276, PR #26 by Rodrigo).
- **A Compact layout, optional.** Settings, You, Appearance, Layout: Journeys as lines, a one-line
  header, the answer as running text. Classic stays the default (CR276).
- **A Journey opens without waiting for the model catalog,** by Rodrigo: later launches went from
  4.00 s to 1.88 s on a Windows 11 workstation, median of 10 (CR271, PR #21).
- **Files and places in the Agentic Field are found again.** A file in a folder the Field omits (`.tmp`,
  `dist`, a dot file) opens from the chat in the system's default application (CR273, PR #24), and Back,
  Forward and Reload find a file opened from a folder's listing (CR272, PR #23).
- **A transparent Journey icon follows the theme,** and the Windows suite runs again after the macOS 12
  source check could not read its own files there (CR269, CR270, PR #25).
- **Still Intel-only and unsigned on macOS;** the Windows bundle is unsigned.

## Where We Started

After alpha.21 the repository had twenty-five external pull requests by one contributor, all evaluated
in rounds in throwaway worktrees and merged with their authorship; a twenty-sixth arrived the day this
release was prepared and was integrated before it. One of them, the cache fix, changes the provider's
source, which makes the installed copy of every connected person out of date. The release carries that
fix and its cure together, and could not carry the first without the second.

## What Changed

- **Settled session (CR274).** `settled-session.ts`, a file of Nautilus's own in the vendored provider,
  is written only when a turn settles cleanly, never for a sub-agent query, and taken once by the next
  turn. It is kept in `anthropic/claude-sessions` in the app's data: ids, a count and a digest, nothing
  of the conversation, and records older than 30 days are removed. Four marked lines of `index.ts` call
  it; a test holds that `index.ts` without them is upstream's file.
- **Provider pin (CR275).** The install is told apart as current, from an earlier pin, or absent. An
  earlier pin's install is updated at launch or when Settings opens, and whoever arrives during an
  install waits for it instead of starting another (up to ten minutes). The update does not wait for a
  Claude Code sign-in: that lives outside the install folder and survives it. Settings and the setup
  count a provider being updated as connected.
- **Activity and Compact (CR276).** The grouping is a pure module that reads the Journey agent status
  and the waiting queue the app already keeps, through the same derivations a Journey row uses. The two
  choices are kept per runtime channel in the renderer's storage, not in the Journey preferences file,
  so an older build reading that file loses none of a person's pins, recents or theme. Every rule of the
  Compact layout sits under `[data-application-layout="compact"]`, and a test holds that it names
  nothing of Settings, dialogs or menus.
- **Model catalog (CR271).** The command takes the app's guard, builds both Pi commands under it and
  releases it only for the wait on Pi, which reads nothing of the app's data.
- **Omitted folders (CR273).** A path inside the Journey folder that names something the Field omits
  takes the route of a file outside it: opened by the system. A missing file, a folder and a path that
  steps out with `..` are still refused.
- **Folder listings (CR272).** A pure function reads the unloaded folders on the way to a place, shallow
  first, before deciding it is gone; Reload reads the shown place's folders again.
- **Icon surface (CR269).** The surface behind a custom Journey image comes from the stylesheet, one
  rule for the dark default and one for the three light themes; the component carries no style.
- **Windows suite (CR270).** The test reads its files through file URLs; nothing in the app changes.

## What Does Not Change

The same Pi, the same Node, the same Core (`mirror-mind@0.44.2`) and the same Conversations as
alpha.21. No schema change and no migration: the home stays at `018_drop_hook_injected`. The
Journey list views and the layout the app opens with are the ones it had.

## Conscious Exclusions

- **The default application opens any extension.** On macOS a `.command` file runs. That already held
  for a file outside the Journey folder and now holds for the omitted folders (CR273). Refusing
  executable files on both routes is a separate decision.
- **The first Claude update downloads the provider again** (about 135 MB, a half minute on a good
  connection). A Claude turn sent during it waits for it. This was exercised in a dev build, apart from
  a turn sent during the update, the person's own bridge being present during it, and the notice for an
  absent provider, which rest on tests.
- **The Activity view shows Failed only for a process that did not start or died.** A provider's own
  error can end a turn as complete.
- **OpenAI sign-in** can fail with `invalid_grant` after the page, also in Pi alone; it is not a
  Nautilus defect and is not fixed here. The sign-in page itself names Nautilus for Mirror (CR264, in
  alpha.21).
- **No signing or notarization,** on macOS or Windows, and **no Apple Silicon build.** The look on
  Safari 15 is still incomplete, as in alpha.21.

## What We Learned

A change that looks local can reach every person who has connected something. The cache fix was one
file; its price was a provider that every connected installation would have found missing, and a
fallback onto the person's own bridge that would have answered in its place, silently. The release is
the pair, and what it adds beyond the fix is a rule: when the app's copy of something is out of date,
it brings it up to date and never answers with another one.

## Next Horizon

Whether to refuse executable files on both external routes, and whether the stylesheet gets fallbacks
for Safari 15.
