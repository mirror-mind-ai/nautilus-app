# v0.4.0-alpha.24 - A way out of Claude, and surfaces that stay opaque on macOS 12

**Date:** 2026-11-24

## Highlights

- **Sign out of Claude from Settings.** Models > Model providers shows **Sign out** beside "Connected
  · signed in to Claude". It asks first: "Sign out of Claude? This signs you out on this computer, in
  Nautilus and in Claude Code in a terminal." Afterwards the line reads "Signed out of Claude" with
  **Sign in** (CR282).
- **Panels keep their background on macOS 12.** Clicking the version number opened an update panel with
  no background, its text drawn over the sidebar. WebKit 15 does not know `color-mix()` and drops the
  whole declaration; the speech bubbles, the search and turn panels, the composer's wrapper and about
  fifty surfaces of the light themes were bare in the same way. Every declaration that uses it now has a
  plain one before it (CR281).
- **A voice component that cannot start says so.** On macOS 12 the published transcription program
  was refused by the system and every recording ended with "Local transcription failed". Now a program
  that cannot start is told apart from a recording that failed, with a sentence that says to remove the
  component and install it again, and Settings shows such a component as damaged when the app opens,
  with its Remove button, instead of ready (CR279, CR280).
- **Voice that starts on macOS 12, for new installs.** The Intel macOS component on the update host is
  a new build, made without Accelerate and for macOS 12.0, published on 2026-11-23 (CR278). It is not
  inside the app: the app fetches it when the voice is installed.
- **Still Intel-only and unsigned on macOS;** the Windows bundle is unsigned.

## Where We Started

A person's Mirror moved to a spare Mac on macOS 12.7.6, and the alphas that followed were tried there.
The update panel was see-through. Voice failed with a sentence that named nothing, and finding the
cause meant running the installed program by hand over SSH: the system refused it for a symbol that
macOS 12 does not have. The app had also taken that program for ready, because it checked a receipt
and file sizes and never ran it. And Claude could be signed in from Settings but not out of it, so
leaving it took a terminal.

## What Changed

- **Sign out (CR282).** A new native command runs the app's Claude Code `auth logout` and then asks
  `auth status`, believing only that: a sign-in still there is an error whatever the logout said, and
  a logout that fails for a person already signed out is a sign-out. It does not run during another
  sign-in and stops a logout that does not end in 30 seconds. CR262 had left the button out because
  the sign-in is shared with Claude Code outside Nautilus; the confirmation now says so in plain words
  instead.
- **Plain fallbacks (CR281).** A PostCSS plugin in the build writes, before each declaration with
  `color-mix()`, one where each mix is its dominant colour: a tint over nothing becomes nothing, and a
  surface mixed from two opaque colours becomes the main one. An engine that knows `color-mix()` uses
  the declaration after it, so nothing changes for it. In the built stylesheet 222 of 227 such
  declarations now have one.
- **Starting and failing (CR279, CR280).** When a transcription fails the app runs the program with
  `-h`; if it cannot be created, does not end, or is killed by a signal, the error is "The
  transcription component cannot start on this computer…". The status runs the same check for a
  component that looks ready. An exit code of its own, even a failing one, counts as started.
- **The component (CR278).** `scripts/build_whisper_cli_macos.sh` builds whisper.cpp 1.8.3 at a pinned
  commit without Accelerate, for macOS 12.0, and `scripts/check_whisper_cli_macos.mjs` refuses a binary
  that needs a newer macOS, links Accelerate or imports a symbol macOS 12 lacks. The result,
  `whisper-cli-v1.8.3-macos12-x64`, transcribes on the macOS 12 Mac.

## What Does Not Change

The same Pi, the same Node, the same Core (`mirror-mind@0.44.2`) and the same Conversations as
alpha.23, and the same Claude Code install, so nothing is downloaded again. No schema change and no
migration: the home stays at `018_drop_hook_injected`.

## Conscious Exclusions

- **A voice component installed before is not replaced.** Someone on macOS 12 to 13.2 who installed
  voice earlier still has the old program. From this alpha the app shows it as damaged when it opens;
  the person removes it in Settings > Sound & Voice and installs it again. Nothing is downloaded
  without being asked.
- **Five colour variables of the light themes** hold a `color-mix()` that a sibling declaration cannot
  repair; on macOS 12 the text that reads them takes the inherited colour. Two container queries and
  two `:has()` rules are still dropped there: labels that should hide in a narrow column, and two small
  menu and notice adjustments.
- **The sign-out does not warn that Claude is the only provider.** Setup still counts an installed
  Claude Code as connected, so the promise would be false; a turn on Claude after signing out says
  so, with a Sign in button.
- **The real sign-out and the real macOS 12 look were not run by the author:** they are the first
  things to check after installing.
- **No signing or notarization,** on macOS or Windows, and **no Apple Silicon build.**

## What We Learned

A feature that only a person on an older system meets is invisible to every check on the newer one: the
tests were green, the Mac the app is built on drew every surface, and the voice program ran there too.
What caught each of these was a run on the old machine, and what keeps them caught is a rule that does
not need that machine: a check that reads what the loader reads, and a build step that does not trust a
declaration the engine may drop. The sign-out is the other kind of lesson: a reason to leave something
out is a judgement about who the product is for, and it can change when that is looked at again.

## Next Horizon

Whether the five variables and the four dropped rules get fallbacks waits for the macOS 12 look after
this alpha. A sign-out that offers the first sign-in again in the same panel, and an automatic reinstall
of a voice component the system will not run, are not proposed yet.
