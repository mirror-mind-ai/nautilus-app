# v0.4.0-alpha.12 - Nautilus on Windows

**Date:** 2026-11-11

## Highlights

- **Nautilus runs on Windows.** The app closes cleanly (CR233), builds and bundles there, carries a
  windowed executable, a per-channel icon and a microphone picker (CR236), and a Windows CI runs the
  frontend build, the suites and the NSIS installer on every change (CR238).
- **The app lists its own Claude Code models** instead of a fixed set (CR237).
- **Voice on Windows.** The whisper.cpp command-line component is built from a pinned upstream commit
  in our own CI, proven, and published to the voice manifest for Windows (CR240).
- **The microphone is found before the first recording,** so a plugged-in Shure MV5 is no longer
  invisible, and the recording status names the microphone that records (CR241, CR242).
- **File links open what they point to.** A Markdown link reads as its label (CR230), an inline code
  span that names a file opens whole (CR231), and a Windows path keeps its drive letter (CR232).
- **Pinned Journeys can be ordered,** and Recent names the group a pinned Journey falls into when it
  has not been used lately (CR228, CR229).
- **Still Intel-only and unsigned on macOS;** the Windows bundle is unsigned.

## Where We Started

Alpha.11 created and deleted personas, but the app was macOS-only: it could not even close on
Windows, the model list was fixed, and voice had no Windows binary. On macOS the new microphone
picker, carried in with the Windows work, showed only "System default" until the first recording,
so a microphone plugged in over USB looked absent. File links in the conversation were plain text:
a Markdown link showed its target, an inline code path did not open, and a Windows drive letter
broke a link in two.

## What Changed

- **Closing on Windows.** The window's close now quits the app, with a single-instance guard so a
  second launch focuses the running window (CR233).
- **Building on Windows.** A platform layer, a windowed executable, per-channel `.ico` icons, a
  microphone picker in Settings, Sound & Voice, the whisper `--audio-ctx` argument and a longer
  provider wait let Nautilus build, bundle and run on Windows x64 (CR236).
- **Windows CI.** A workflow runs the frontend build, the TypeScript check, the full vitest suite,
  `cargo test --locked`, the win-x64 runtime layout and the NSIS installer on push, on pull requests
  and on demand (CR238). A second, hand-run workflow builds the Windows voice binary (CR240).
- **The app's own models.** The Claude Code model list is read from the app's own provider instead
  of a fixed list, so it stays current (CR237).
- **Voice on Windows.** The whisper.cpp command-line component is built from the pinned `v1.8.3`
  commit in CI, checked to depend only on Windows' own libraries and to transcribe a sample with the
  published model, then published to the voice manifest under a Windows entry; the macOS entry and
  the models are unchanged (CR240).
- **Finding the microphone.** The picker tells a microphone the system is hiding from no microphone
  at all; when the list is hidden it offers to allow the microphone so the system names them, without
  recording, and it follows microphones plugged in or out (CR241). While recording, the status names
  the microphone from the recording itself, so a fall back to the system default is named truthfully
  (CR242).
- **File links.** A Markdown link reads as its label and opens its target (CR230); an inline code
  span that names a file opens the whole path (CR231); a Windows path keeps its drive letter instead
  of splitting at the colon (CR232). These build on the working-folder link work: a link opens in the
  selected Journey's own folder (CR225), and a file link in a Journey with no folder is handled
  (CR226).
- **Pinned and Recent.** The Navigator can order pinned Journeys, Recent marks its groups (CR228),
  and a pinned Journey that has not been used lately is named by that in Recent (CR229).
- **A returning launch** is no longer held on provider discovery (CR227).
- **Persona medals** are bundled and chosen, never inferred: a medal is shown only after a choice,
  so Remove image returns to the diamond (CR234, CR235).
- **The message field stays in view** when many files are attached (CR239).

## What Does Not Change

The same Pi and the same `mirror-mind@0.44.0` core as alpha.11. No table in a home's database
changes. On macOS the app behaves as before, with the new microphone picker the one visible
addition. The voice manifest's macOS binary and both models are untouched.

## Conscious Exclusions

- **No signing or notarization,** on macOS or Windows.
- **No Apple Silicon build;** macOS remains Intel-only.
- **The Windows app and the Windows voice binary have not been installed from a published artifact
  on a Windows machine** by the time of this note; the CI proves the build and the suites.
- **No undo** for the medal or microphone choices beyond changing them again.

## What We Learned

A picker written and proven on one platform can be blind on another: the WebView on macOS hides the
microphones until one is allowed, where Windows exposes their ids. The same CI that builds the
Windows voice binary caught it depending on the Visual C++ runtime, which a fresh Windows would not
have; building from source in our own CI is what made that visible. A medal that follows an id is a
coincidence, not a choice; appearance is the Navigator's to set.

## Next Horizon

Installing the Windows app and the Windows voice binary from their published artifacts on a Windows
machine, signing and notarization, and a conversation held with a persona (CV-015's next design
step).
