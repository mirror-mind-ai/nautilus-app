# v0.4.0-alpha.29 - Paste a screenshot, and an Activity view that reaches the conversation

**Date:** 2026-11-27

## Highlights

- **A pasted image is attached.** Pasting a screenshot, or an image copied from another program, into the
  composer keeps it as a file in the folder the Journey works in, under `pasted/`, and attaches it like any other
  file. Pasted text stays text (CR304, PR #34 by Rodrigo).
- **Pasted images stay out of Git.** The `pasted/` folder is made with a `.gitignore`, so a Journey whose
  folder is a repository does not commit its screenshots with the work (CR304).
- **On Windows, a file copied in Explorer can be pasted.** It is attached by its own path, nothing is copied,
  and two files at once are both attached. On macOS this is not read yet, and a paste behaves as in the
  previous point (CR305, PR #35 by Rodrigo).
- **The Activity view reaches the conversation you are working in.** Under a Journey's row it lists the
  conversations in motion and those a message was sent in during the last 24 hours, each leading to itself
  (CR301).
- **Every Journey can have its own image.** The limit of 32 custom images, and of 256 entries in the
  appearance preferences, is gone (CR302).
- **Closing a chapter by hand switches the sidebar to Activity,** as sending a message does, without saving
  that choice of view (CR303).
- **The footer stops announcing the size from before a compaction.** If a compaction ended while another
  Journey was on screen, the conversation showed the old size as measured, and the prompt cache notice
  repeated it. It now shows `?` until the next turn measures (CR306, PR #36 by Rodrigo).
- **Still Intel-only and unsigned on macOS;** the Windows bundle is unsigned.

## Where We Started

Alpha.28 was a small round: a sentence before an update closes the app, and two fixes from Rodrigo. After it
the work came from use. A conversation being worked in could not be entered from the Activity view without
leaving it for Recents. A screenshot could not be attached without saving it by hand first, which is what
Rodrigo's two paste contributions address. The 32-image limit on custom Journey images had been a safety
count more than a need, and a compaction that ended while another Journey was open could leave a wrong size on screen.

## What Changed

- **Activity (CR301, CR303).** A conversation shows under its Journey when a run is in motion in it or a
  message was sent in it within 24 hours; the Journey row itself always leads to the Journey's own
  conversation. A manual compaction switches to the view when it starts, and a collapsed sidebar stays
  collapsed.
- **Journey images (CR302).** The count limits are removed in the native import, the renderer and the
  preferences parser together, so an older preference file is not reset. Each image is still checked: 5 MiB
  at most for the source, 2 MiB after normalising, known formats, 512 px, a regular file and no symlink.
- **Pasted images (CR304).** One native command saves the bytes under `pasted/pasted-<date>-<time>.<ext>` in
  the folder the header shows after "Working in", resolved as a turn resolves it. The extension follows what
  the bytes are, an image over 20 MB is refused in words before anything is written, and no file is ever
  replaced. The line that says why a file was not attached reads in the light themes.
- **Pasted files on Windows (CR305).** The clipboard's file list is read when the Composer asks, and used only
  if every pasted name matches exactly one path on it; otherwise the paste is treated as an image with no
  file. A pasted file that is not an image and has no path is refused with a sentence that points to the
  paperclip and to dropping the file on the window.
- **The context reading (CR306).** A stored measurement is dropped when the branch Pi holds ends in a
  compaction whose usage is still pending, and only if it is the reading that was judged; the estimate a
  watched compaction leaves is kept.

## What Does Not Change

The same Pi, the same Node, the same Core (`mirror-mind@0.44.2`), the same Claude Code install and the same
Conversations as alpha.28. No schema change and no migration, the home staying at
`018_drop_hook_injected`. Two native commands are new (`save_pasted_image`, `inspect_clipboard_files`) and
both are serialised and off the main thread. No new crate; on Windows three more modules of `windows-sys`,
already in the tree, are enabled.

## Conscious Exclusions

- **macOS does not read a file copied in Finder.** What the system WebKit hands to a paste was not observed
  in a way that settles it, so the behaviour of a Finder paste is the one described for images, and a file
  that is not an image gets the refusal sentence. Reading the pasteboard's file URLs would be its own change.
- **The paste of a screenshot on macOS** runs the same code as on Windows (the Composer's paste event, the
  default Edit menu), but what the system WebKit hands to the page was not observed by the assistant as a
  separate case; the Navigator's validation did not say which system it was done on.
- **A removed attachment stays on disk.** "Remove file" and "Clear all" take the image off the message and
  leave `pasted/` as it is.
- **Going back to an older build with more than 32 custom Journey images** makes that build reset the
  appearance preferences, because its parser refuses a file with more than 256 entries.
- **Validated by the Navigator, with gaps.** All six changes were reported validated before this release.
  The reports were short, and the records say what each one leaves unexercised.
- **A compaction does not keep a conversation in the Activity view,** and the compaction's own estimate is
  not carried to a conversation that is not on screen.
- **No signing or notarization,** on macOS or Windows, and **no Apple Silicon build.**

## What We Learned

Two limits that looked like caution were counts, not protections: the real protections are on each file. And
a folder the app now writes into is a folder other tools read; saying what stays out of Git is part of making
the folder.

## Next Horizon

The update from alpha.28 to this release on Windows and macOS, and the first paste of a Finder file on a Mac.
Then the Windows pages of the site. And, when Apple answers, signed and notarized distribution.
