# v0.4.0-alpha.26 - Prompt cache notices, a Journey's memory, and a steadier Activity list

**Date:** 2026-11-25

## Highlights

- **Prompt cache notices, off until asked for.** In Settings › Advanced, a notice above the composer of a
  conversation of 50K tokens or more says when the model's prompt cache is about to expire and what the
  next message would re-process, with Compact now beside it. After each turn a receipt says what the
  usage reported (CR285, CR291).
- **What Mirror kept from a Journey.** "View Journey Memory…" in a Journey's menu opens a read-only
  panel: the memories grouped by kind, with counts, an excerpt that opens to the whole text, and a link to
  the conversation each came from when the app knows it (CR286).
- **A context reading that stays measured.** The "~" of an estimate no longer lingers in the composer
  footer after a few turns: every turn gets its own few attempts to read what the model used
  (CR288).
- **An Activity list that waits for your hand.** After a click the list keeps its order for four seconds,
  so the row you aim at does not slide away; and sending a turn shows the Activity view (CR289, CR290).
- **A release route for Windows.** The release process can now build, sign and publish the Windows
  installer and its updates apart from the macOS route, and the repository carries a one-line install
  for Windows. Nothing is published to Windows people by this release alone (CR287).
- **Still Intel-only and unsigned on macOS;** the Windows bundle is unsigned.

## Where We Started

Alpha.25 left three pull requests from the same contributor open and four loose ends of the assistant's
own. The prompt cache of a long conversation expires after about five minutes, and the app said nothing
about it. What Mirror had kept from a Journey could be read only in a terminal. The Windows installer
was built by hand. In the field, the context reading fell back to an estimate after a few turns, and the
Activity list moved under the pointer while a person was choosing a row.

## What Changed

- **Prompt cache notices (CR285).** An option off by default, stored per runtime channel. With it on, the
  notice reads the cache's remaining life from the last answer and the conversation's size. After a turn,
  the receipt says whether the last message read from the cache or re-processed the conversation, only as
  far as the reported usage supports it, including a call that wrote most of the context beside a partial
  read. The notice and the receipt are readable in the light themes. It never compacts by itself.
- **Settings › Advanced (CR291).** A tab of its own between Updates and Diagnostics holds that option;
  it left You, which keeps what a person sees every day.
- **Journey memory (CR286).** A native command and the host read the Journey's memories from the home's
  database, read-only, 200 at most by default. The panel changes nothing and is readable in the light
  themes.
- **The context reading (CR288).** The budget of re-reads after a turn resets when a turn starts, so a
  conversation of many turns keeps measuring.
- **The Activity list (CR289, CR290).** The order is held for four seconds after a click, by pointer or
  keyboard. Sending a live turn switches the sidebar to the Activity view without saving the choice; a
  collapsed sidebar stays collapsed.
- **The Windows release route (CR287).** A workflow on every release tag builds and tests the installer;
  a script on the publisher's machine signs it with the updater key, which never enters CI, and
  publishes it with its manifests after the macOS route; a script installs it from the repository in
  one line, checking the hash first.

## What Does Not Change

The same Pi, the same Node, the same Core (`mirror-mind@0.44.2`), the same Claude Code install and the
same Conversations as alpha.25. No schema change and no migration: the home stays at
`018_drop_hook_injected`. One new native command, `list_journey_memories`, and one new host call. The
Journey rows of the sidebar and the other Activity behaviour are as before.

## Conscious Exclusions

- **The memory panel reads the Core's table directly.** The host opens the home's database read-only, which
  is outside the Core's host-read contract. The Core has captured the proper route (listing, and later
  forgetting, a Journey's memories); the panel moves to it when it exists. It cannot forget a memory.
- **The cache notice is only as good as the usage the model reports.** A provider that reports no cache
  figures gets no receipt, and conversations under 50K tokens get no notice.
- **A turn's own measurement is not kept against a lagging read.** If the "~" shows for a moment after a
  turn, that is the file not yet written; keeping the turn's number would hide an aborted turn.
- **The Windows route has not yet published anything.** The installer reaches Windows people, and their
  updates start, only when its publication is run on its own, after this release.
- **The Invocation mode stays in Models.** Moving it to Advanced is its own change, for a later release.
- **No signing or notarization,** on macOS or Windows, and **no Apple Silicon build.**

## What We Learned

Two of the contributor's panels read as white on white in the light themes, and the first version of the
cache receipt said less than the model's own numbers showed. A feature that speaks about cost or time
has to be checked against a real conversation, in every theme, before it is called done; the field run
found in minutes what the tests had not been asked.

## Next Horizon

The first real Windows publication, which also lets installed Windows apps be offered updates. The
Invocation mode in the Advanced tab. And, when Apple answers, signed and notarized distribution.
