# v0.4.0-alpha.25 - Activity rows that lead to the conversation, and a dev server that starts on Windows

**Date:** 2026-11-25

## Highlights

- **An Activity row says where the work is.** When a Journey is at work in a conversation inside it
  instead of in its own, the row names the conversation before the operation (`Nova Feature · bash npm
  test`), draws the nested status mark a Journey row already draws, and leads to that conversation from
  the row and from the mark. The Journey's own work still comes first (CR284).
- **A Need you row opens the answer.** When a turn ends in a conversation inside the Journey, the row
  says so and opens that conversation, where the answer, the interruption or the failure is, and no
  longer the Journey's own conversation, where it is not (CR284).
- **The development server starts on Windows.** `npm run tauri:dev` stopped with `EBUSY` while the
  native crate compiled, because the watcher followed files the build locks. It now ignores
  `src-tauri`. This is for people who build the app; the installed app does not change (CR283).
- **Still Intel-only and unsigned on macOS;** the Windows bundle is unsigned.

## Where We Started

Alpha.22 brought the Activity view, which groups every Journey as Need you, Working or Idle. It dropped
a distinction the Journey rows already made: work in a conversation inside a Journey showed as the
Journey's own, with nothing saying where, and the row opened the Journey's own conversation. After a
turn ended, "Finished. Open it to read the answer" led to a conversation that did not hold the answer,
and finding it meant opening the Journey's conversations one by one.

## What Changed

- **Live work (CR284).** For work in a conversation, the Activity input carries the conversation, and
  the row and the status mark lead there through the route CR134 already uses for a Journey row. With
  several workspaces of one Journey at work, the line describes the one the row is about.
- **An ended turn (CR284).** The finished-turn attention keeps the workspace of the run that finished,
  and an interrupted or failed outcome reads it from the turn journal, which names the thread of every
  turn. A conversation is claimed only when it is known not to be the Journey's own.
- **The dev server (CR283).** `server.watch.ignored` in `vite.config.ts` lists `src-tauri`. Vite serves
  nothing from there on any platform.

## What Does Not Change

The same Pi, the same Node, the same Core (`mirror-mind@0.44.2`), the same Claude Code install and the
same Conversations as alpha.24. No Rust change, no stored format change, no schema change and no
migration: the home stays at `018_drop_hook_injected`. The Journey rows of the sidebar, in every other
view, behave as before.

## Conscious Exclusions

- **When an answer counts as seen is unchanged.** It is seen when its Journey is opened, so a turn that
  ends in one conversation while the person is in another of the same Journey is acknowledged at once
  and never reaches Need you. Changing it would also change how long the Ready mark stays on a Journey
  row in the other views; it waits for a decision.
- **One record per Journey.** If two conversations of a Journey end a turn while the person is away, the
  row is about the newest. A Journey row's mark in the other views still leads to a conversation only
  for live work.
- **Seen on Windows, not on macOS.** The author ran both changes on Windows 11. A failed turn and a
  manual compaction that end in a conversation were exercised by unit tests only, and an interruption
  found after a restart leads to the Journey until its own thread is known.
- **No signing or notarization,** on macOS or Windows, and **no Apple Silicon build.**

## What We Learned

A view added to show the state of many Journeys inherits the distinctions of the view it summarizes, or
silently loses them. CR276 summarized the sidebar and dropped where the work was; a contributor who
used it with real conversations found it in a day. The fix reuses the route that already existed instead
of drawing a second one.

## Next Horizon

Three more pull requests from the same contributor are open and not yet evaluated: a notice before a
conversation's prompt cache expires, a panel of what Mirror kept from a Journey, and a Windows installer
with its own update manifests. They are not part of this alpha.
